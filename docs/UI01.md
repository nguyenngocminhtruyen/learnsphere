# Phase UI-01 — LearnSphere frontend demo

This separately authorized milestone adds an interactive frontend to the completed Phase 0 foundation. It does not implement the backend phases represented by these screens. All course, learner and creator operations use typed fixtures and in-memory state in the existing Next.js App Router application. No API, AWS, model provider or paid service is called.

## Implementation plan and route map

1. Add shared design tokens and reusable controls, typed course/lesson/enrollment/quiz/generated-draft models, fixtures and a local repository boundary.
2. Build the public discovery, course detail and student learning experience.
3. Build creator management, editing and the AI Studio review flow.
4. Verify translations, keyboard controls, responsive layouts and local interactions with unit and real-browser tests, then run the production build.

| Area | Routes | Primary behavior |
|---|---|---|
| Discovery | `/` | Original hero artwork, categories, featured/recommended courses, working search and navigation |
| Catalog | `/courses`, including `?q=` and `?subject=` | Combined search, subject/level/language filters, sorting and empty state |
| Course | `/courses/[slug]` | Overview, outcomes, skills, native curriculum accordion, instructor and demo enrollment |
| Learning | `/my-learning` | Enrolled/in-progress/completed courses, progress and continue links |
| Player | `/learn/[courseId]/[lessonId]` | Collapsible curriculum, video illustration/reading/quiz preview, previous/next, completion, notes/resources and canned tutor chat |
| Assessment | `/quizzes/[id]` | Required answer selection, scoring, feedback, retry and progress update |
| Demo access | `/login`, `/register` | Form validation, password visibility and explicit demo-only entry |
| Creator | `/admin`, `/admin/courses` | KPI cards, activity, draft/published search and edit/create navigation |
| Editor | `/admin/courses/new`, `/admin/courses/[id]/edit`, alias `/builder` | Course details, editable modules/lessons, save draft and explicit publish preview |
| AI Studio | `/admin/ai-studio` | Metadata-only document selection, settings, timed generation, retryable failure, lesson/quiz review and approve draft |

Shared components include `SiteHeader`, `CourseCard`, `CourseGrid`, `SearchBar`, `CourseFilters`, `CurriculumAccordion`, `ProgressIndicator`, `LearningSidebar`, `AITutorPanel`, `AdminSidebar`, `DataTable`, `CourseEditor`, and `GenerationWizard`.

## Design and dependencies

LearnSphere uses original branding, code-window illustration and geometric course artwork drawn in native HTML/SVG/CSS. No Coursera trademarks, logos, scraped assets, remote fonts or external stock imagery are included. Colors follow the brief: blue `#1858D8`, navy `#102A43`, surface `#F5F7FB`, green `#16A37A`. The layout uses a shared spacing/type system, light surfaces, subtle borders and responsive grids.

The existing application initially had Next.js/React and lint/type tools only. UI additions are Tailwind CSS with its PostCSS plugin, Lucide icons, and a composable shadcn-style Button using Radix Slot/CVA/clsx/tailwind-merge. New test tools are tsx and Playwright. Dependency versions and the pnpm lockfile are checked in. No separate component framework, backend runtime or alternative frontend scaffold was introduced.

## Demo behavior and limitations

- The provider holds course edits, enrollment, progress and approved drafts in memory. Refreshing resets the workspace to fixtures. Only the non-sensitive EN/VI language preference is persisted in localStorage; no cookies or sessionStorage are used for demo identity.
- Forms demonstrate validation, not authentication. Enter invented data only. Form values are cleared after successful demo submission; no account, token or server session is created. Inputs remain disabled until client handling is ready, and are disabled entirely without JavaScript, so native form submission cannot accidentally place credentials in a URL. The creator workspace is openly accessible as a demo. Client checks are illustrative UX, never production authorization.
- Video is an interactive preview illustration, not a real media stream. The tutor returns a clearly labeled canned response. Source files are represented by filename/size only: no bytes are parsed, transmitted, stored or sent to a model. Generated lessons and quiz review examples are deterministic samples, not model output or verified source citations.
- Enrollment and completion are idempotent in local state. Unknown/draft courses and cross-course completion inputs are rejected by the mock state helpers. Quiz results are client-side demo results and can be inspected in the bundle.
- Notes and chat live only while their lesson/player is open. Bookmarks only toggle within the rendered card. The resource button downloads a local plain-text companion generated from sample lesson content; it does not fetch a protected resource.
- AI Studio approval saves a course as a draft. Publication requires a separate explicit editor action with content validation. No automatic publishing takes place.
- UI chrome has matching EN/VI dictionaries and a visible language switch, including mobile navigation. Course titles, descriptions, lesson text and assessment content are fixture content in their authored language; switching the UI is not course-content translation.
- All displayed instructors, enrollment counts, ratings and activity are illustrative fixture data. There is no payment, real credential or certificate issuance.

## Local commands

From the repository root:

```sh
pnpm --dir apps/web install --frozen-lockfile
pnpm --dir apps/web lint
pnpm --dir apps/web typecheck
pnpm --dir apps/web test
pnpm --dir apps/web build
pnpm --dir apps/web dev --port 3100
```

Open `http://localhost:3100`. Docker and all backend services can remain stopped for this UI demo.

Browser checks:

```sh
# If Chrome is unavailable, install Playwright's Chromium once:
pnpm --dir apps/web exec playwright install chromium
pnpm --dir apps/web test:e2e
# Or test an already-running production build:
UI_BASE_URL=http://localhost:3101 pnpm --dir apps/web test:e2e
```

The Playwright configuration uses system Chrome when present, otherwise Playwright Chromium. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` supports another local Chromium installation. Without UI_BASE_URL, the runner starts/reuses a dev server on port 3100. Traces for failures are placed in ignored `apps/web/test-results/`.

Exact verification commands executed (repeated failing iterations were corrected before the final run):

```sh
pnpm --dir apps/web install --frozen-lockfile
pnpm --dir apps/web lint
pnpm --dir apps/web typecheck
pnpm --dir apps/web test
pnpm --dir apps/web build
pnpm --dir apps/web start --port 3101
UI_BASE_URL=http://localhost:3101 pnpm --dir apps/web test:e2e
pnpm --dir apps/web audit --prod --json
.venv/bin/python scripts/check_contracts.py
.venv/bin/pytest apps/ai-service/tests -q
(cd apps/api && ./gradlew test --tests com.edutech.ContractTest)
```

Final results: **8/8 unit tests**, **9/9 browser tests (24.7s)**, **2/2 Java contract tests**, **3/3 Python contract tests**, OpenAPI validation/breaking-change self-test passed, production build exited 0. Java/Python contract checks did not require running domain services. The existing Python test client emitted an upstream httpx deprecation warning; browser tooling emitted a NO_COLOR/FORCE_COLOR warning. Neither failed a check. The dependency audit covers production frontend packages only, not a comprehensive repository security review.

During verification, a screen-reader-only table heading escaped its mobile scroll container; positioning the container fixed real page overflow. Explicit select labeling and scoped test locators resolved accessible-name ambiguity. Native course tabs now implement roving focus/arrow keys. Creator skills input preserves comma-separated edits, and generation language affects generated content independently of UI locale. The final build and browser run include these fixes.

## Future integration points

Replace the typed fixture repository/provider boundary with Java public API adapters when the corresponding backend phase is authorized. Move identity and authorization to Cognito/Java, course and learner operations to Java, and AI orchestration behind Java's scoped private Python integration. Future work must add actual media delivery, upload validation, streaming/cancellation, server-side quiz scoring and durable storage with permission tests. Current mock data must never become an authorization source. Existing OpenAPI contracts remain authoritative and unchanged.
